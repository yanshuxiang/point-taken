## 已确认的事实

- 录音入口：`app/macos/Sources/PointTakenApp/Capture/Board.swift`
  - `start(locale:directory:)`（约 2601 行）：请求麦克风权限 → `beginAudio()`
  - `beginAudio()`（约 2654 行）：读格式 → `installTap` → `engine.prepare()` / `engine.start()`
  - `stop(_:)`（约 2875 行）：停引擎、移除 tap
- 失败时界面上可能出现的提示（都在 `beginAudio()` 里）：
  - 「没找到可用的麦克风」—— 读到的格式采样率或声道数为 0
  - 「麦克风启动失败：设备格式变化 / …」—— `installTap` 抛 ObjC 异常（约 2745 行）
  - 「麦克风打不开：…」—— `engine.start()` 抛错（约 2755 行）
  - 「麦克风未获准，不能保存录音」—— 权限被拒（约 2634 行）
- `Resources/*/Dictation.strings` 里的麦克风文案（`dictation.mic.*`、`voiceprint.mic_failed` 等）
  在 Swift 代码里已无引用，是删上游听写功能后留下的，和这个问题无关。
- 系统日志 `log show --predicate 'process == "point-taken"'` 近 7 天查不到任何记录，
  没拿到真实报错码。
- 用户当前默认输入：MacBook Air 内置麦克风，1 声道，48 kHz（`system_profiler SPAudioDataType`）。

## 推断的原因（未验证）

1. **`AVAudioEngine` 整个 App 生命周期只建一次**（约 2475 行 `private let engine = AVAudioEngine()`），
   每次录音都复用。两次录音之间如果输入设备变了（连/断 AirPods 等蓝牙耳机——蓝牙开麦会把采样率
   从 48k 降到 16k/24k；插拔外接麦克风；系统里换默认输入），`inputNode.outputFormat(forBus: 0)`
   读到的是旧格式，和硬件对不上，于是 `installTap` 抛异常或 `engine.start()` 报 -10868 / -10875。
   这符合「时好时坏、重启 App 就好」的现象。
2. **暂停后结束不会真正 stop 引擎**：暂停用 `engine.pause()`，之后 `engine.isRunning == false`，
   `stop(_:)` 里 `if engine.isRunning { engine.stop() }` 被跳过，引擎带着旧状态留到下次。
3. **没处理 `AVAudioEngineConfigurationChange`**，录音中途换设备不会重建，引擎会悄悄停掉。

## 建议修法

- 每次 `beginAudio()` 新建 `AVAudioEngine`（把 `let engine` 改成 `var`，开录时重建），
  至少在开录前 `engine.stop(); engine.reset()`。
- 格式改用 `input.inputFormat(forBus: 0)`（反映当前硬件），并在采样率为 0 时给出明确提示。
- `stop(_:)` 无条件 `engine.stop()` 并移除 tap。
- 订阅 `AVAudioEngineConfigurationChange`：录音中换设备时移除 tap、按新格式重装、重启引擎；
  注意 `BoardAudioArchive`（WAV 写入）和 `BoardLiveSpeech` 都按开录时的格式初始化，
  格式变了需要转换（`AVAudioConverter`）或标记 `audioArchiveIncomplete`。
- 相关测试在 `app/macos/Tests/PointTakenCoreTests/`，改完补测试并跑 `swift test`。
