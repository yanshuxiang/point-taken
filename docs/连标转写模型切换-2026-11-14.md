# 标注语音模型

> 当前方案：实时字幕与结束后的完整转写统一使用设置中选定的模型。下文前两节是修复过程记录，其中“实时字幕使用苹果”的设计已经废止。

用户要求：设置页可切换模型、显示当前选择；保留 API 配置和本地模型下载。独立听写仍关闭。

原问题：API 已保存，但 BoardSpeech 的完整音频复核固定调用 AppleSpeech，原模型选择没有控制标注。安装包也缺少运行脚本目录。

本次实现：
- 设置 → 模型与 API → 完整转写模型，使用独立配置 record.board.transcriptionModel，默认保持苹果系统识别。
- 可选可用的本地模型和已配置的云语音服务。切换时明确显示本机处理或发送原始音频给 API。
- 开始录音时固定该次模型；设置变化只影响下一次录音及用户主动重新转写。实时字幕继续使用系统识别。
- 所选模型通过现有 note 接口读取完整 WAV，显式指定 model-id，不走独立听写、声纹过滤或润色，不自动下载或切换提供方。
- note --segments 返回原始音频时间。豆包请求 utterances；时间缺失或对应文字不完整时保留完整文字和较粗的片段范围，不伪造逐词时间。
- 模型失败、空结果及重复解码异常不会删除实时文字或原始音频。实际选择写入转写状态.json。
- 随安装包携带原有脚本运行目录和此次更新，启动同步到 ~/.point-taken/skill；旧目录留有备份。凭据仍存钥匙串。

## 实时字幕统一模型（取代前述苹果实时方案）

用户指出实时字幕也必须跟随选定模型。原先仅切换结束后的完整转写是不完整实现，现已改正：

- 录音开始时固定同一个模型，同时用于实时字幕和结束后的完整音频转写；设置变化从下次录音生效。
- 豆包实时使用 bigmodel_async，结束后仍用 bigmodel_nostream 复核完整音频。两者是同一所选豆包模型的实时／完整接口；接口名称不等于服务端返回的权重版本证明。
- 非苹果模型不会申请或启动苹果语音识别。网络或鉴权失败明确显示，不自动切换苹果；原始音频仍独立保存。
- 其他所选模型复用指定模型进行短窗口转写；本地模型仍在本机，支持 API 的模型仍用对应 API。
- 菜单分别显示实时字幕与完整转写的模型。实时调用.json 记录实际提供方、模型、请求编号和状态，凭据不入日志。
- 暂停同时停止输入实时音频，恢复后续接；正常结束先接收实时尾句，再执行完整转写。退出保存仍保留音频和已有文字，不能将退出保存当成完整转写成功。
- 苹果语音权限说明改为“仅选择苹果系统识别时需要”。API 配置与本地模型下载保留。

验证：50 项相关测试通过，涵盖结束前出字、暂停续接、模型一致、失败不切换提供方。已签名程序的真实通道测试使用合成语音，不读取或上传用户历史录音。
