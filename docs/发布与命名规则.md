# 发布与命名规则

Point Taken（中文名「懂你意思」）在 GitHub Releases 上发布 macOS 安装包。以下名字都由版本号推出来，不要手写别的叫法。

## 版本号

- 用语义化版本 `主版本.次版本.修订号`，如 `0.1.0`。
  - 修订号：只修 bug。
  - 次版本：加功能，旧用法不受影响。
  - 主版本：有不兼容的改动（1.0 之前可以在次版本里改）。
- 唯一来源是 `app/macos/Info.plist` 的 `CFBundleShortVersionString`；`CFBundleVersion` 和它保持一致。
- 预发布在后面加 `-beta.N` / `-rc.N`，如 `0.2.0-beta.1`。

## 各处名字

| 东西 | 规则 | 例子 |
| --- | --- | --- |
| Git 标签 | `v<版本>` | `v0.1.0`、`v0.2.0-beta.1` |
| Release 标题 | `Point Taken <版本>` | `Point Taken 0.1.0` |
| 安装包 | `PointTaken-<版本>-macos-<架构>.dmg` | `PointTaken-0.1.0-macos-arm64.dmg` |
| 校验文件 | 安装包名 + `.sha256` | `PointTaken-0.1.0-macos-arm64.dmg.sha256` |
| dmg 卷名 | `Point Taken <版本>` | 挂载后显示 `Point Taken 0.1.0` |

- 架构写 `arm64`（Apple 芯片）、`x86_64`（Intel）或 `universal`（两者合一）。
- 文件名只用英文、数字、`.` 和 `-`，不带空格和中文，方便下载链接和命令行。
- 预发布在 GitHub 上勾选 Pre-release。

## 怎么打包、发布

1. 改 `Info.plist` 里的版本号，提交。工作区要干净，dmg 才对得上某个提交。
2. 打包：`app/macos/build-dmg.sh`，产物在 `dist/`（不进仓库）。
3. 打标签并发布：

   ```bash
   gh release create v0.1.0 dist/PointTaken-0.1.0-macos-arm64.dmg dist/PointTaken-0.1.0-macos-arm64.dmg.sha256 --title "Point Taken 0.1.0" --notes "..."
   ```

## 说明

- 本地的 `v0.3.0`～`v1.0.22` 等标签是从上游带来的，不属于 Point Taken 的版本，不要推到 origin。
- 现在用 Apple Development 证书签名，没做公证；别人第一次打开要右键选「打开」，或在「系统设置 → 隐私与安全性」里放行。
